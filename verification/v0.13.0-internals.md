## Resource and failure probes

Native read helpers use a 96-word frame, eight managed roots and three linked
records: path/scan storage and fd, row-table current/old mappings, and name-arena
current/old mappings. Rows contain offset, byte length, scalar length, kind and
observation ordinal. They contain no managed pointers. Sorting and value
materialization start after close; allocation failures retain the linked maps
for the existing runtime cleanup bridge. Image ABI remains v6.

The checker reads actual Machine instructions to validate fixed frame boundaries,
callee-save effects, root publication/removal and the ownership CFG. It rejects
managed allocations on paths with a live directory fd. Encoded metadata checks
the v6 context, descriptors and literal v3 event headers independently.

`v013-review-latch-flow-proofs` additionally checks the emitted latch control
flow for all three directory operations in normal and test profiles. Deleting,
inverting, clearing or bypassing the final decision is rejected; an equivalent
zero-branch/internal-jump form is accepted. Raw-map adapter corruption and
loss of the phase-specific EINVAL decision are rejected independently.

Host tests pin raw buffers for each FFI call and observe descriptors around
failure paths. Host staging is managed by Common Lisp, so mmap/munmap ownership
cases are native-specific. Close injections follow a real close. Cleanup-result
injections follow a real unmap; they test classification without leaking the
fixture mapping. Malformed-record fixtures skip unsafe syscalls; deliberately
unrecoverable mappings are left for the isolated child's process teardown, not
reported as successfully released by the API.

`v013-native-runtime-cleanup` and `v013-growth-and-subject-allocation` inspect
syscall traces before the terminal diagnostic. `v013-cleanup-map-boundaries`
covers external ENOMEM, internal EINVAL, invalid alignment/size/fd and a cyclic
link. Known records are processed without following a forged link. The global
primary-runtime bridge bounds chain traversal to aligned, increasing stack
addresses; it preserves the original language failure if cleanup also fails.

`v013-review-map-syscall-errors` injects actual mmap ENOMEM/EINVAL at every
directory acquisition in a growth fixture, including old table/arena mappings.
The trace oracle tracks successful mappings by address and length and requires
all directory scratch to be unmapped before diagnostics. It also checks single
descriptor closure, createDirectory path acquisition and the inherited file
allocation-failure boundary. `v013-review-map-runner-errors` connects both map
outcomes to initialization/body stages, parent accounting and resource recovery.

These are controlled failure probes, not evidence of recovery from every
physical OOM, process kill or arbitrary memory corruption. No RSS claim or
whole-filesystem transactional guarantee is made.

## Private reporting cases

The event layout remains 40 bytes with the same tags/kinds and channels. Version
is 3. Private child status 123 means detected internal inconsistency; 124 retains
transport failure. Only native test images use the private status. A normal main
returning 123 remains an ordinary application status.

| Case | Evidence |
|---|---|
| A committed, B internal, C not started | Real scan EBADF and child-error/close-EBADF combinations: parent 3, 1 passed/1 aborted/1 not_run, no C effect. |
| Initializer versus body | Same real helper faults at stages 1 and 2; stage-specific context, child reaped and parent fds recovered. |
| Before ready/before delegation | Synthetic child exits 123; after-spawn synchronization observes reap first. No gate, all not_run, empty stdout and unknown stage. |
| Bare exit 3, signal, private 124 | Synthetic children establish continued abnormal outcomes for the first two and command I/O interruption for 124. |
| Terminal contradiction/partial suffix | Synthetic 123 with either condition produces internal interruption without a normal result commit. |
| Previous assertion/panic | Real helper fault preserves the earlier failed/errors classification and aborts only the current attempt. |
| Post-commit parent failure | Inherited `v011-committed-context-recovery` and runner command-boundary groups retain committed results and report context once. |
| Primary/secondary parent failure | Prior I/O failure before interpreting reaped 123 stays 2; reporting failure after internal primary stays 3. |
| Language allocation plus cleanup failure | Host storage plus internal close failure, normal native and real test images preserve allocation-failed/status 4; no private internal result replaces the language primary. |
| Ordinary Err and main 123 | Public integration tests explicitly assert or discard Err; ordinary main 123 remains 123 in both backends. |
| Version/record corruption | A v2 child fixture is rejected by the v3 parent before delegation; an independent v2 reader boundary rejects a real v3 ready before delegation. Independent byte fixtures reject invalid versions/kinds and encoded native v3 headers reject mutations. No second installed compiler is claimed. |
| Normal profile/internal diagnostic failure | Host internal condition and native static diagnostic return 3; an injected EPIPE on the native diagnostic keeps 3. Test internal terminal emits no terminal event or diagnostic payload. |

`v013-runner.lisp` identifies the synthetic subprocess cases; these are separate
from `v013-internal-runner-real-helper`, which calls the actual directory API.
Producer/consumer constants are shared, while test oracles pin literal values.
No public flag, environment variable or source-level fault hook is introduced.
