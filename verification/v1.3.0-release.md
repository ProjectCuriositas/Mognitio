# Mognitio 1.3.0 release validation

The [implementation review record](v1.3.0-review.md) pins the corrected mgnc
source, fixed 1.2.0 seed, 55 acceptance conditions, 63 additional regressions
and 21 resource cells. The release version changes the normal toolchain identity;
it does not replace that backend or change mgnc's fixed seed.

## Source and compiler gates

Run the complete source suite on the release candidate through the final
acceptance-edges result. Verify the checksum manifest and validate candidate
and tagged source archives against their exact tracked bytes, with no Git metadata.
Run the documented examples, ordinary compilation and standalone execution.

Build mgnc from the archived source with the pinned 1.2.0 seed. Compare the
compiler image to the accepted image and run the added review regressions.
The existing complete acceptance and performance evidence applies only when
all executable mgnc sources, the fixed seed, and generated compiler image match.
A package smoke test is not a replacement performance measurement.

## Frozen distribution gates

From clean main, build the formal normal toolchain once using the locked
Ubuntu image, runtime, input core and notice in packaging/build-lock.json.
Package that immutable payload into one Debian package and one offline bundle.
Verify identical payload bytes, component identities, modes and ownership.

Explicitly inspect both archives and the payload inventory: neither may include
mgnc, its source project, or an experimental-compiler launcher.
Only mgn and mognitio-lsp are installed as normal toolchain commands.
The repository source archive retains compiler/mgnc for explicit source builds.

Run protocol, analysis, boundary, projection, token, installer recovery/failure,
signing/trust and package-permission checks on the frozen payload.
Check actual 1.2.0 to 1.3.0 offline upgrades on Ubuntu 24.04 and 26.04.
Validate the unchanged consumer against the final frozen normal compiler.

## Signing and publication

Follow the current [distribution procedure](../packaging/README.md).
Create an immutable implementation tag at the verified main commit, freeze draft
assets, and dispatch production signing with the exact manifest digest.
Use a tag that directly identifies the commit, as required by the signing workflow.
No version integration branch or documentation tag is created.

Download every signed draft asset, compare frozen bytes and independently verify
the production signature before publishing. Run the package-acceptance workflow
on both supported userlands, including unrelated non-root execution after root
installation. Publish only the frozen verified assets.

Update the APT registry through a separate reviewed pull request, preserving
all older releases. Verify production deployment, then install and upgrade from
the public HTTPS repository with signed-by on both supported userlands.
Check reinstall, removal, purge, LSP, and standalone execution after removal.

## Evidence and boundaries

Record candidate, main, tag, source archive, build identity, artifact hashes,
signing, package acceptance and APT deployment independently.
Keep the frozen bytes and execution logs in permanent release evidence.

Only Linux amd64 and the documented Ubuntu userlands are in the distribution
matrix. Namespace userland checks share a host kernel.
The VS Code extension and consumer have independent release processes.
Experimental mgnc is source-built only; this release does not establish
self-hosting or general 1.x source support in mgnc.
