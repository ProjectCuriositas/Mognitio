# v0.11.0 runner review fixes

The reviewed implementation is `8937912daa8ed719ea4c5233f327ebea59d2ae77`.
Three focused regressions failed on that revision before the fixes: host storage
recovery lost its summary, a frame-register mutation was accepted, and a
committed failure lost its test context. The final candidate and cumulative
results are pinned in this change's implementation pull request.

## Host storage conditions

Attempt execution, suite execution, process finalization, artifact cleanup,
and recovery reporting catch both `error` and `storage-condition`. A host
storage condition becomes command exit 3, retaining any earlier primary
failure. Started tests with unknown results become aborted; later tests remain
unstarted. Known results are not rolled back. Cleanup continues where possible,
preserving the first failure's classification and reporting residual paths.

`v011-parent-storage-recovery` injects a condition derived directly from
`storage-condition`, outside the `error` hierarchy, before execution, during a
real infinite native body, and before summary. It verifies result accounting,
exit 3, test identity/stage, reaped processes, and unchanged parent fd inventory.
A native program allocation-failure control remains errors/exit 4 and continues
the suite. `v011-storage-during-cleanup` checks storage failure as both primary
and secondary, retained completed counts, deleted images, and residual paths.

These are recoverable fault injections. They do not claim that diagnostics can
always allocate successfully after actual process-wide memory exhaustion.

## Returning helper destinations

An independent closed opcode table describes every allowed instruction's
explicit or implicit register writes. Preserved registers cannot be destinations.
RBP/RSP changes are admitted only in the checked prologue, final epilogue, and
the balanced call to the independently checked event helper. Unknown effects
are rejected. Existing stack bounds, context writes, and call checks remain.

`v011-helper-destination-preservation` uses caller-save positive controls and
42 mutations across six explicit-destination opcodes and seven preserved
registers, including RBP and RSP. It also rejects five misplaced stack operations
or unsupported-opcode controls. Existing live-register pressure and actual
native computation fixtures remain active.

## Committed diagnostics

The stdout result flag and stderr context flag are independent. Normal and
recovery paths use the same idempotent context reporter for failed, errors, and
aborted results. The context flag is set after a successful write. A broken
stderr sink is not retried as if reporting had succeeded.

Assertion site metadata is retained with the committed result. Test native
assertion helpers send the site-bearing terminal event; the parent renders the
assertion location once with the selected test context. Reporting therefore
does not depend on whether child stderr was drained before a command failure.
Ordinary standalone assertions retain their native static diagnostics, and
panic payload bytes are forwarded without reinterpretation.

`v011-committed-context-recovery` injects immediately after result commit and
after context/before result output, with ordinary completion as a control.
Assertion, panic, and arithmetic failures retain their result class; command
failure exits 3. The test checks exactly one context, the body stage, an
independently counted helper assertion span, no extra starts, resource recovery,
and no duplicate output when the context reporter is called again.

## Reproduce

All four groups are in [v011-review.lisp](../tests/v011-review.lisp) and are part
of the ordinary ASDF gate, alongside the existing v0.11 fault matrix and v0.10
project regressions:

```sh
sbcl --noinform --script scripts/test.lisp
git diff --check
sha256sum -c verification/SHA256SUMS
```

The public behavior and 72-case acceptance ledger are unchanged. The additional
internal gates are D11-R10 (storage recovery), R11 (destinations), and R12
(committed diagnostics). See the [implementation record](v0.11.0.md) and
[case ledger](v0.11.0-testing.md). This change does not release the version.
