## Implemented behavior

Normal entry is `Function(List<String>): Int`; arguments are strict UTF-8 and
the application returns a status from 0 through 255. The launcher transfers raw
bytes on a separate framed descriptor and preserves program stdin. Standard I/O
functions are explicit imports and ordinary callable values with nominal errors.

Host and native backends use incremental UTF-8 validation and geometrically
grown staging. File APIs validate paths and regular-file targets, create with
mode 0666 subject to OS restrictions, loop over partial transfers, and release
owned resources before returning. Stdout/stderr add no bytes of their own.
Expected errors remain Results; signal-based write failures do not bypass them.

Test protocol v2 separates application stdout, application stderr, private
runtime diagnostics, and terminal events. Application chunks are escaped and
identified on runner stderr. Results and the summary remain on stdout. The
existing start/commit/abort ledger and resource cleanup boundaries are retained.

## Resource and signal evidence

Real RLIMIT_FSIZE=1 runs exercise partial output `A` followed by EFBIG for `AB`,
including native/CL files and redirected stdout/stderr. Discarding the Err still
allows status 0. A separately prepared test child can assert the error and pass.
A runner report positioned at its file limit returns command status 2 while
retaining a committed passed result and recovering owned resources.

Native syscall traces establish close/munmap before the allocation-failure
diagnostic. Close-failure fixtures perform the real close before injecting a
failure result. Repeated I/O and small-heap collection retain live Strings and
arguments without accumulating file descriptors or temporary roots.

The host guard saves/restores the complete Linux amd64 kernel signal action:
handler, flags, restorer, and all supported mask bits. Nested, partial-setup,
storage, nonlocal-exit, and restoration-failure cases are covered. Native
bootstrap failure returns 3; test bootstrap failure uses private status 124 and
the parent's command status 2, before user initialization/start delegation.

## Limits

Validation is specific to Linux amd64. Controlled allocation/storage injections
do not prove successful recovery from every physical memory-exhaustion scenario.
Concurrent filesystem replacement, external termination, power-loss durability,
throughput, and peak RSS are not certified. There is no directory traversal,
public File handle, defer statement, atomic write API, or compatibility shim for
the former Unit main.
