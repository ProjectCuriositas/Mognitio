# v0.10.0 implementation verification

This record covers the project-module implementation on the v0.10.0 version
branch. The base implementation is `33e054d3983a44819c161e337be87a4364253703`.
The exact final candidate commit and command results are recorded in its pull
request. Version-branch completion does not imply a release.

## Implemented behavior

- Strict TOML 1.0.0 manifest schema, fixed `src` discovery, and conventional Unit main.
- Per-file namespaces, group imports, aliases, public declarations, and named witnesses.
- Original nominal identities, private-signature rejection, definition-site templates,
  and module-local witness visibility with project-wide pair uniqueness.
- Full-project static checks, deterministic dependency initialization, silent run/native
  success, and terminal initialization failures.
- Strict UTF-8 paths, escaped diagnostics, reader-before-open file-kind checks,
  duplicate physical input rejection, and preservation of all project inputs.
- Deterministic static ELF generation, standalone execution, and atomic publication.

The project verifier independently reconstructs declaration ownership, public flags,
imports, lexical resolutions, source order, dependencies, reachability, the entry,
and the runtime plan. Mutation tests corrupt these records and require internal
failure. Existing type, specialization, SSA, root, ABI, and metadata verifiers
remain active.

## Reproduce

```sh
sbcl --noinform --script scripts/test.lisp
git diff --check
sha256sum -c verification/SHA256SUMS
```

The full gate includes the Lisp suite and the Python project CLI suite. The
latest complete run results and exact HEAD are recorded in the pull request.
Tests run on Linux amd64 with SBCL 2.6.0 and Python 3 as a non-root user.
Failures stop the gate; absence of a required process-tracing facility is a failure.

The public CLI cases cover imports, signature exposure, witness visibility,
entry diagnostics, unreachable-module checking, initialization stopping,
manifest schema, UTF-8 path/body distinctions, FIFO/socket rejection, output
aliases, future-source prevention, and relocated cold/warm deterministic bytes.
A native executable is also run without project sources or a usable compiler PATH.
All 14 distributed projects and the inherited positive language matrix use Unit
main through both backends. Small-heap tests force collection across module
boundaries while closures and hidden concrete contract values remain live.

## Regression boundaries

The test-only Boolean kernel adapter preserves independent generated-tree,
writer-syscall, ABI, and fault oracles. It is not loaded by `bin/mgn` and does
not expose a compatible single-source mode. Its results supplement, rather than
replace, project CLI conformance. See [test coverage](../tests/README.md).

Project publication faults cover lowering, verification, encoding, ELF construction,
writing, flushing, mode setting, closing, and replacement. Source and existing
artifact bytes are compared after failures. Special-file probes assert that the
source reader was not invoked. The examples check rejects an empty catalog.

Generated samples and fault injections are bounded. They do not certify
concurrent filesystem replacement, external termination, uncatchable resource
exhaustion, or power-loss durability. TOML parsing is limited to the prescribed
schema; no generic TOML API, package resolver, or external dependency manager
is provided. No main integration, tag, or GitHub Release is part of this work.

## Review follow-up

Symbolic generic applications already satisfy `nominal-type-p`, and
`context-type` expands their shape without requiring concrete type arguments.
The reported private-type exposure was rejected on the reviewed implementation.
Additional unused alias, product, sum, template parameter/result, nested Function,
and phantom type-argument cases now guard that behavior. A malformed proof
created with the producer visibility check bypassed must also fail verification.
The visibility walker is shared; this fault test does not establish independence
from bugs in that shared walker.

Filesystem classification visits directories before considering source suffixes.
The README now distinguishes empty `.mgn` directories from non-directory
special files. Tests cover both an empty directory and invalid namespace
components when it contains a source, preserving the existing artifact on failure.
PATH invocation is tested from an ordinary project directory with relative
manifest/output arguments. The compiler's real `bin` directory belongs on PATH;
the source checkout remains necessary for the launcher.
