## CLI and text I/O

Normal entry is `Function(List<String>): Int`. Arguments are strict UTF-8 and
the application returns a status from 0 through 255. The former Unit entry is
not supported. Language tests retain `Function(): Unit`.

Explicit imports from `Std\Io` provide ordinary function values for whole-file
text reads and writes, stdin reads, stdout writes, and stderr writes. Expected
I/O failures use nominal Result errors. Owned resources are released within
the operation; partial writes may remain after failure. New regular files
request mode 0666 subject to the OS umask/default ACL rules.

SIGPIPE and SIGXFSZ do not bypass expected write-error handling. Host execution
saves and restores signal actions. Test instances receive stdin EOF, keep
application output separate from runner reports, and share the filesystem.

The [37-condition ledger](v0.12.0-conformance.md), [14 internal gates](v0.12.0-internals.md),
[implementation record](v0.12.0.md), and [review corrections](v0.12.0-review.md)
record coverage and evidence limits. Review regressions cover repeated stdin
consumption after invalid UTF-8, startup status after failed diagnostics, and
test command status after signal restoration failure.

Use the real compiler `bin` directory on PATH as described in [usage](../README.md).
The [file converter](../examples/file-converter/README.md) demonstrates runtime
arguments and text I/O. The inherited [test guide](../examples/testing/README.md)
and [72-case ledger](v0.11.0-testing.md) describe language test behavior.

## Distribution and limits

Use the tagged source archives. Other hosts/targets and prebuilt compiler
packages are not validated. Directory traversal, binary I/O, public File
handles, defer, atomic file writes, and advanced test framework features are
outside this increment. Backwards compatibility is not guaranteed before v1.0.0.

Controlled storage/allocation injections do not prove recovery from every
physical memory-exhaustion scenario. Broken output sinks or externally
terminated runners cannot guarantee complete reporting or cleanup. Infinite
tests have no built-in timeout. Finite tests do not certify unbounded resources,
concurrent filesystem replacement, power-loss durability, or performance.
Existing collector complexity limits remain unchanged.
