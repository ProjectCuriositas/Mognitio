# v0.15.0 release validation

The v0.15.0 release contains one immutable Linux amd64 toolchain payload in a
Debian package and an offline installer bundle. The release manifest records
its source commit, build identity, component identities, artifact sizes and
SHA-256 hashes. GitHub release notes record the executed final-artifact results.

## Frozen artifact checks

Build from the tagged main merge commit using the pinned Ubuntu 24.04 runtime,
input core and license notice in packaging/build-lock.json. Package exactly once;
retain the generated bytes for validation and publication. Verify that the
deb and bundle contain byte-identical payloads and that every component reports
the same build identity. Never rebuild or replace an asset under a published tag.

The separately versioned VS Code 0.1.0 VSIX uses publisher mognitio and extension
ID mognitio.mognitio. Its GitHub-only preview had another publisher ID. Include
the tested stable VSIX in the language release and signed artifact manifest.

Run the full Lisp suite, v0.15 protocol/boundary/token/projection suites, installer
ownership and interrupted-operation suites, and packaging/trust checks.
Run the exact packages on Ubuntu 24.04 and 26.04 userlands: install, reinstall,
update, remove, run/build/test, and LSP analysis after package replacement.
Run the stable installed VSIX in VS Code 1.91.0 on both supported userlands,
including diagnostics, semantic colors, delayed results, manifest saves,
Restricted Mode, disabled extension and child-process cleanup.

The userland matrix shares the test host kernel; it is not independent-kernel
or additional-architecture validation. Upgrade predecessor packages used only
as fixtures must be clearly identified and never published as formal releases.

## Signing and publication

The [public signing key](../packaging/mognitio.asc) and
[fingerprints](../packaging/signing.json) pin the certification primary and the
bundle signing subkey. Initial publication uses GitHub and GitHub Pages under
one account; an independent trust channel is not yet available.

The sign-release workflow accepts only main, checks that the version tag names
its exact source commit, and downloads a draft release. It checks the approved
manifest digest, formal identity and every listed artifact before signing.
The signing environment holds only the bundle secret subkey and passphrase;
the primary secret remains offline. An existing signature is never overwritten.

After signing, download and independently verify the complete draft assets with
scripts/verify-bundle.py and the current public key. Only then publish the release.
The APT repository consumes the exact published tag, signed manifest and Debian
asset. Verify installation again from the public HTTPS repository on both OSes.

## Reproduction commands

```sh
sbcl --noinform --script scripts/test.lisp
python3 tests/v015-release-signing.py
python3 tests/v015-toolchain.py --payload /path/to/frozen/payload
python3 tests/v015-installer.py --bundle /path/to/verified/bundle
git diff --check
```

See each tests/v015-*.py entry point for the additional protocol, limits, trust,
projection and failure-recovery fixtures. Signing tests use disposable keys.
