# 1.2.0 implementation progress

## Integer value parameters

The first increment extends type, alias and template parameter lists with
compile-time integer parameters. The value domain is the existing signed
64-bit Int domain, including negative values. Literal parentheses and negative
zero normalize without changing type identity. Type parameters and integer
parameters remain separate categories.

Generic substitution, instance keys, free-parameter discovery, imported
declarations, source verification and semantic tokens retain that distinction.
Values do not become runtime bindings or captures. Existing type-only generic
programs keep their meaning.

## Focused verification

- tests/v120-value-arguments.lisp: host and native identity, signed boundaries,
  alias and template forwarding, captured values, rejected categories and
  expressions, and a corrupted generic-parameter proof.
- python3 tests/v120-projects.py: imports and aliases across modules, run,
  build, language tests, analyzer acceptance/rejection, non-execution of a
  panic initializer, and preservation of an existing artifact on rejection.
- The active ASDF suite includes both groups.

The implementation commit and exact full-suite result are recorded in its pull
request. Focused results do not establish completion of the entire version.

## Remaining implementation

Fixed-width integers, Bits, Bytes, numeric methods, binary publication and the
reference emitter still require implementation and their cumulative acceptance
checks. No 1.2.0 release or distribution is established by this increment.

## Numeric scalar increment

The numeric scalar increment implements standard Signed/Unsigned marker identities,
Bits construction, fixed-width integer identities, widths 1 through 64,
typed scalar literals, and width/literal constraint propagation through aliases
and template applications. Type parameters remain distinct from value parameters.
The host and native backends implement checked fixed-width arithmetic, explicit
integer conversion, integer/bit interpretation, bitwise methods, shifts, and
indexing. Generic method application preserves ordinary field comparisons.

The numeric suite checks every width, full unsigned 64-bit values, runtime
overflow and unreachable expressions, conversion boundaries, forwarding,
and static rejection through run/build/analysis. Additional Lisp checks cover
Product/List/closure lifetime under normal and forced GC, and independently
reject altered constraint, literal, and catalog records.

Bytes, byte encoding, binary publication, the reference emitter, cumulative
v1.2.0 acceptance, and release remain pending.
