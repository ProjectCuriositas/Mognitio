# 1.2.0 implementation progress

## Integer value parameters

The first increment extends type, alias and template parameter lists with
compile-time integer parameters. The value domain is the existing signed
64-bit Int domain, including negative values. Literal parentheses and negative
zero normalize without changing type identity. Type parameters and integer
parameters remain separate categories.

Generic substitution, instance keys, free-parameter discovery, imported
declarations, source verification and semantic tokens retain that distinction.
Values do not become runtime bindings or captures. Existing type-only generic
programs keep their meaning.

## Numeric scalar increment

The numeric scalar increment implements standard Signed/Unsigned marker identities,
Bits construction, fixed-width integer identities, widths 1 through 64,
typed scalar literals, and width/literal constraint propagation through aliases
and template applications. Type parameters remain distinct from value parameters.
The host and native backends implement checked fixed-width arithmetic, explicit
integer conversion, integer/bit interpretation, bitwise methods, shifts, and
indexing. Generic method application preserves ordinary field comparisons.

The numeric suite checks every width, full unsigned 64-bit values, runtime
overflow and unreachable expressions, conversion boundaries, forwarding,
and static rejection through run/build/analysis. Additional Lisp checks cover
Product/List/closure lifetime under normal and forced GC, and independently
reject altered constraint, literal, and catalog records.

Binary publication, the reference emitter, and cumulative v1.2.0 acceptance
remain pending. Release is a separate stage.


## Bytes and encoding increment

Bytes is an immutable owned byte sequence with a cached length and a dedicated
native GC descriptor. Its payload is never scanned as references. Construction
from ordinary integers reports the first invalid element before constructing
Bytes; construction from Bits<8> preserves all 256 bit patterns. Operations
include length, indexing, append, concatenation, half-open slicing, and equality.

Explicit ByteOrder controls encoding and decoding. Widths not divisible by eight
return BitWidthError or BinaryDecodeError, and decoding requires an exact length.
No text encoding is involved. Semantic length overflow and allocation failure
use the existing fatal runtime-failure contract. The private test event protocol
is version 4 so older readers cannot misclassify the added failure kind.

The CLI suite independently derives endian vectors, checks all byte values,
signed index boundaries, exact lengths, invalid widths, and static type errors.
Lisp checks exercise Product/List/closure retention under forced GC, length and
allocation failures, and corrupted Core/catalog proofs.

## Binary publication increment

publishFile accepts Bytes and returns structured phase/publication errors.
It validates the unmodified path, checks existing entries without following the
last symlink, stages in the owned parent, writes to completion, closes the file,
and publishes with renameat2(RENAME_NOREPLACE). Ownership cleanup never removes
the destination. The enabled kernel/filesystem profile and post-publication
cleanup applicability are documented in v1.2.0-publication-profile.md.

Private tests cover raw syscall failures, EINTR retries, short writes followed
by success or failure, primary-error preservation, unknown commit outcomes,
and synchronized commit races. Corrupted machine records are rejected by an
independent frame/ownership/no-replace verifier. Filesystem tests cover raw
bytes, permissions, ACLs, entry kinds, trailing slashes and real file-size limits.

The reference emitter and cumulative version acceptance are still pending.
