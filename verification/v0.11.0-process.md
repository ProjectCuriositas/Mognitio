# v0.11.0 process and register boundary evidence

## Host boundary

The test adapter uses raw FFI to glibc `posix_spawn` on Linux amd64. File actions
map stdin to `/dev/null`, stdout/stderr to separate pipes, the event writer to
fd 3, and the gate reader to fd 4; descriptors from 5 upward are closed. Parent
pipe descriptors are relocated above these destinations before spawn.
The compiler host requires glibc 2.34+ for `addclosefrom_np`.

On SBCL 2.6.0.debian and glibc 2.43, syscall tracing observed `clone3` with
VM/VFORK synchronization, the four `dup2` actions, `close_range`, `execve`,
and a matching parent `wait4`. No Lisp continuation runs in the child.
glibc's Linux `spawni.c` was inspected for child signal setup, file actions,
exec, error publication, immediate exit, and parent reaping of failed children.
This is source inspection plus runtime evidence, not a formal proof of libc.

`v011-pre-exec-failure-boundary` injects invalid dup/close actions, a nonexecutable
image, and pipe creation failure. These return command exit 2 before any test
starts, with empty stdout, no summary, and no owned process or leaked fd.
glibc reaps children that fail inside spawn; only a successful returned PID is
registered in the adapter. No independent exec-error pipe is used.

## Start commit

Before raw gate write, interrupts are deferred. A successful one-byte write
is immediately followed by the preallocated execution-delegated slot store.
The fd is nonblocking and the byte buffer and pointer are prepared in advance.
Generated SBCL code was inspected for both `delegate-start` and `raw-write`:

- Interrupt-enable state is disabled before the foreign-call path.
- For count 1, the return range -1/0/1 is boxed as a fixnum; the bignum branch
  is unreachable for this operation.
- No call or allocation occurs between successful return and the slot store.
- Interrupt handling becomes possible after the stored start fact is retained.

This claim concerns the bounded commit path, not the entire function. Pointer
boxing and setup outside that region can allocate. To repeat the inspection,
load the ASDF system and disassemble `mognitio.testing::delegate-start` and
`mognitio.testing::raw-write` on the target SBCL version.

`v011-start-delegation-commit` tests successful write followed by interruption,
EPIPE, EINTR before interruption, EINTR then success, and an SBCL deferred
interrupt request. The test-only write replacement requests an interrupt;
production code contains no hook in the commit region. Generated-code review
checks that distinction. Started/unknown becomes aborted, unsent stays not_run,
and the flag survives cleanup and repeated ledger synchronization.

## Ownership and transport

A single session guard owns prepared files from initial acquisition through
runner cleanup. Preparation-return and runner-entry faults exercise the same
owner. Image-generation/save faults clean partial files; cleanup failure retains
the original command failure and reports residual paths separately.

Test result state is separate from process state. Real child faults cover
ready-before-gate, body/initialization interruption, launch failure after one
success, and parent interruption after reap. Re-finalizing a reaped handle is
tested with kill, wait, and close operations replaced by rejecting probes,
preventing operations on numbers that could now belong to other resources.
Parent `/proc/self/fd` snapshots and saved wait state are checked independently.

Independent literal records exercise framing, partial reads, malformed complete
records, truncation, ordinal/sequence/site validation, and status disagreement.
A real native child emits records matching those fixtures. Closing the actual
event channel after ready causes the native writer to exit privately with 124;
the parent classifies that status as report I/O failure rather than panic.
Closed public stdout and stderr are also tested through real CLI processes.

## Returning stage notification

The stage writer does not allocate or create a GC safepoint, but it is a
register-clobber barrier. Independent liveness verification and the producer
both account for it. Helper verification checks permitted clobbers and frame
restoration separately from nonreturning assertion failure helpers.

`v011-stage-register-proof` forces four values across the marker: without the
marker they use R8-R11; with it they spill. A forged R11 allocation and a missing
barrier are rejected. Invalid helper frames, callee-save writes, and allocating
calls are rejected. `v011-native-stage-pressure` executes a standalone native
IR fixture whose four values must still sum to 46 after notification.
Template closures and small-heap collection are checked separately through the
source-level runner and both ordinary backends.

The cumulative command and exact candidate revision are recorded in the
implementation pull request; see [verification](v0.11.0.md).
