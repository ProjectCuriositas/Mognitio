## File close failure precedence

The first file close consumed descriptor ownership before final scratch
cleanup. Its invalid-owned-descriptor result could therefore bypass the later
internal-failure latch. On the host backend, a cleanup internal condition was
also hidden by an earlier ordinary I/O condition.

Native code now classifies the first close immediately, retaining internal
failure until all remaining mappings are released. Final cleanup cannot clear
that latch. An internal close skips managed success materialization. Host code
classifies EBADF from an owned close as internal and selects the primary by
failure class. Existing language runtime/storage failures retain precedence.
Neither backend retries close; ordinary external errors still preserve a
previous I/O failure or become Cleanup when no earlier failure exists.

The fault adapter can substitute the first-close result after a real close,
allowing resource observations without using process teardown as the oracle.
Separate strace syscall substitution reproduces the original path. All fault
controls remain internal and absent from public source, options and environment.

## Scalar root lifetime

The prior checker recognized root store/load instructions but did not reject a
clear moved between the String allocation and List node allocation. The new
CFG worklist tracks input/partial-List/scalar root identities, temporary RAX/RDX
references, root linking, allocation, element storage and List publication.
Every reachable node allocation requires the live scalar root. Clearing or
overwriting it before publication, including on just one branch, is rejected.
Direct frame-address escapes cannot bypass tracked root writes. A harmless
control-flow detour remains valid, independently of exact instruction adjacency.

## Primary outcome lifetime

The phase checker now follows cleanup control flow from the initial snapshot
through the final ownership unlink. It separately considers no primary, a
kind-based primary and a raw-errno primary. Abstract classes cover every error
kind and errno, rather than treating one sampled value as the whole class.
Register comparison facts refine branch edges. A new outcome requires an
unlocked primary and exactly one matching phase capture; later cleanup cannot
change it. Frame-address escapes and post-cleanup phase writes are rejected.
Existing shape, descriptor, ownership and internal-latch checks remain active.

## Validation

`tests/v014-review.lisp` is part of `scripts/test.lisp`. The initial four probes
failed on the reviewed base: host/native first-close propagation, scalar early
clear, and the directory primary guard inversion. All now pass.

The expanded review tests cover all eight I/O APIs with guard inversions and
bypasses, a guard accepting only one particular error kind, an extra phase
write during error construction, conditional scalar clearing, slot overwrite,
and direct frame-store mutation. Positive normal and harmless-detour helpers
also pass. These are mutation controls, not claims that ordinary source
previously generated those corrupted helpers.

Resource tests cover read/write success and body failure followed by internal
close, actual close/unmap ordering before terminal reporting, ordinary external
close contrasts, host descriptor balance, and original runtime/storage condition
identity. Native ENOMEM during scratch acquisition plus EBADF during cleanup
retains allocation failure. Controlled faults do not certify arbitrary corruption
or physical resource exhaustion.
