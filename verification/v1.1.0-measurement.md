# Native workload comparison

The comparison harness runs immutable baseline and candidate images with the
same source files and inputs. It records compiler revisions, binary and source
hashes, literal/static-object counts, raw output, process time, and peak RSS.
Each image has one warm-up and five measured executions per cell. Execution
order alternates. Result validation runs after the process timer stops.

Build each set using its own compiler checkout and the same consumer checkout:

```sh
python3 tests/v11-measure-build.py --compiler BASELINE --levi CONSUMER --output baseline-images
python3 tests/v11-measure-build.py --compiler CANDIDATE --levi CONSUMER --output candidate-images
python3 tests/v11-measure.py --baseline baseline-images --candidate candidate-images --evidence comparison
```

The output directory must be new. Use `--resume` with the same evidence path,
images, sources, and harness hashes after an interruption. Completed records are
not rerun or replaced. Partial output remains available. Raw evidence contains
local environment and command paths; sanitize it before public distribution.

The 74 cells cover scalar creation, text assembly, scanning, persistent symbol
tables, combined use, consumer helpers and controls, a large consumer scan, and
bounded-live repetition. The executable does not change with input size.
The consumer drivers use the production `validTitle` and `assembleFragments`
helpers. Their expected result is asserted by each driver.

The profile separates correctness, improvement, absolute resource budgets, and
regression limits. No timing or memory improvement compensates for another
failed condition. Noisy cells are rerun in full at most twice, retaining every
batch. Timeouts are recorded rather than converted to elapsed-time successes.
A baseline cell with only timeouts has no relative comparison; mixed outcomes
cannot pass. A wrong result or candidate budget failure is retained across
retries. The machine must have at least 8 GiB available at the start, and no
other build or benchmark should run concurrently.

`v11-measure-check.py` exercises rejection of incorrect results, overlapping
improvement distributions, noise, time/RSS regressions, absolute-budget failure,
mixed baseline outcomes, and real process timeouts. The ordinary workload oracle
also checks native execution inside an empty mount namespace containing only
the executable and input files.

Private counter builds are separate from timing artifacts. Symbol fixtures use
the unchanged lookup implementation and a driver with no other string-equality
call site. They count actual equality-helper calls and allocations, covering
first/middle/last hits, misses, duplicate registration, different name lengths,
and 1,024 unique names. A linear search still needs up to N name comparisons;
registering N unique names needs N(N-1)/2 comparisons before explicit lookups.
String byte comparison and allocation are additional costs.

The built-in workload suite also runs with a 64 KiB managed cap and collection
on every allocation. This verifies retained token text, Unicode scalar
positions, persistent symbol branches, and text assembly under reclamation.
It complements process RSS measurements rather than being inferred from them.

This document describes the method. Completed measurements and their source
identities must be recorded separately before claiming performance acceptance.
