# Native allocation and collection in 1.1.0

The native runtime searches a free-only first-fit list instead of scanning
allocated blocks for every allocation. Split and unlink operations update that
list without allocating; sweep coalesces adjacent free blocks and rebuilds it
in arena order. Existing immutable values, object headers, allocation failures,
and language APIs retain their contracts.

Collection uses a bounded temporary worklist to scan each reachable object
once. A temporary allocated-start index is constructed independently from the
physical partition. Dynamic references must match an indexed allocated start
before the runtime reads their headers. Static references still require exact
matches to known static objects. Interior and free pointers remain invalid.

The workspace contains a queue, per-arena records, and one marker byte per
eight arena bytes. For mapped arena bytes M and arena count A, its unrounded
size is M/4 + M/8 + 24A + 32 bytes. Checked page rounding precedes mmap.
The workspace is released after collection; it is not cached across collections
or counted as managed arena capacity. Peak process memory includes it.

The private context metadata version is 7. Existing field offsets are unchanged.
The free head is at offset 288 in the normal profile and 336 in the test profile;
total context sizes are 304 and 352 bytes respectively. Raw free links are not
language roots, and allocated headers clear the free-link words before value
construction. This metadata version is not a public ABI compatibility promise.

## Verification mechanisms

- Independent snapshot reader reconstructs the physical partition before
  following the actual free head. Both normal and built-in-test profiles cover
  empty lists, split thresholds, exact fit, skipped free blocks, tail unlink,
  coalescing, and multiple arenas.
- Runtime head-zero and middle-head mutations preserve the physical partition
  but must fail coverage checks. Reader mutations cover cycles, interior and
  allocated pointers, truncation, old formats, and profile mismatches.
- Snapshot writer runs at stable points before another allocation or collection.
  Closed and full observation descriptors fail instead of producing acceptance.
- A separate index reader reconstructs allocated starts from raw physical blocks
  and compares every marker byte. Missing, interior, and free markers are
  rejected independently of the runtime index producer.
- Workspace acquisition failure and corrupted queue capacity use the existing
  failure paths. Normal and test profiles retain their diagnostic/exit classes.
- Syscall tracing verifies repeated workspace mmap/munmap pairs, leaving only
  the managed arena. Forward, reverse, and cyclic graphs scan each object once.
- Existing cumulative value, root, descriptor, failure, I/O, and runner tests
  remain part of the gate. The compiler-workload oracle checks complete results
  on both backends with separate expected values.

Run the cumulative gate from the repository root:

```sh
sbcl --noinform --script scripts/test.lisp
git diff --check
```

GC instrumentation uses separate private builds. Allocation free-list visits,
static candidate comparisons, dynamic marker probes, index construction visits,
object scans, and collections are distinct observations. Instrumented artifacts
do not establish normal-artifact timing, RSS, or public protocol behavior.

## Limits

First-fit remains linear in the number of free blocks. Static-reference matching,
arena-range selection, descriptor dispatch, and example symbol-table lookup have
their own costs. No universal constant-time allocation or linear-time GC claim
is made. Performance acceptance requires its separately recorded comparisons;
structural verification alone is insufficient. No release is published by this
implementation record.
