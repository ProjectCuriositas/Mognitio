# v0.11.0 implementation verification

This record covers language assertions, compiler-defined declaration metadata,
and native test execution on the v0.11.0 version branch. The base implementation
is `6e68d8587a44f5f52f32971d7321bc81fc033937`. The implementation pull request
records the exact candidate commit and final command results. Version-branch
completion is separate from release validation.

The [runner review follow-up](v0.11.0-review.md) records subsequent corrections
and their independent regressions without changing the public contract.

## Delivered behavior

- `@test` metadata on module-level immutable `Function(): Unit` bindings,
  including aliases, factory values, and private declarations.
- Closed compiler attribute validation, related locations for duplicates and
  invalid targets, and required/actual type diagnostics.
- Single-evaluation `assert` statements in executable scopes, dedicated failure
  exit 5, and static source locations in standalone artifacts.
- Entry-independent whole-project validation and deterministic discovery;
  ordinary run/build entry, visibility, completion, and initialization remain.
- A fresh native image/process per test, all images prepared before execution,
  continuation after test failures, and separate command-failure handling.
- Structured private reporting independent of panic text, explicit aborted and
  unstarted accounting, bounded payload forwarding, and owned-resource cleanup.

The [example](../examples/testing/README.md) uses the public command.
The [case ledger](v0.11.0-testing.md) maps all 72 acceptance IDs to executable
fixtures. Internal proof and process-failure tests supplement those observations;
an ID appearing in a table is not itself evidence of execution.

## Reproduce

```sh
sbcl --noinform --script scripts/test.lisp
git diff --check
sha256sum -c verification/SHA256SUMS
./bin/mgn test examples/testing/mognitio.toml
```

The full ASDF gate runs Lisp tests, `tests/v010-projects.py`, and
`tests/v011-testing.py`. Each failure stops the gate. Tests were run as a
non-root user on Linux amd64, SBCL 2.6.0.debian, glibc 2.43, and Python 3.
The process adapter requires glibc 2.34 or later on the compiler host.
Generated ordinary ELF executables remain independent of libc and the compiler.

The Lisp `Processes` counter counts calls through the general process harness;
it does not include every native child spawned by the new test runner or the
separate Python suites. Report all three suite summaries without conflating
these counters with a total OS-process census.

## Independent boundaries

The checked metadata and TestPlan verifiers reconstruct ownership, identity,
coverage, and ordering from source ASTs. Entry mutations reject incorrect roots,
initializers, callees, and stage markers. Allocation verification independently
rejects values left in clobbered registers across returning stage notifications.
An actual native pressure fixture checks that four live scalar values survive.

Position tests use literal expected UTF-8 byte ranges and CRLF scalar positions,
including a helper failure on the second assertion of a line. A moved native
artifact preserves identical diagnostic bytes after its project is deleted.
Panic payload tests include raw NUL/LF, multibyte text, misleading failure words,
and data larger than pipe capacity.

The [process boundary record](v0.11.0-process.md) distinguishes mocked faults,
real child-process observations, source inspection, and generated-code review.
Existing source, generic, capture, ABI, GC, artifact publication, deterministic
build, and input-preservation tests remain part of the cumulative gate.

## Limits

There is no test timeout, parallel scheduler, test filter, persistent image
cache, user-defined attribute, macro, coverage, benchmark, or fixture system.
An externally killed runner cannot promise a summary or cleanup. A failed
report sink cannot promise complete output. Resource exhaustion is reported
where detected; no crash recovery or sandbox for future external effects is
introduced. Performance and other libc/SBCL architectures were not validated.
