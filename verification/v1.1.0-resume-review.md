# Mognitio 1.1.0 measurement resume review

## Finding and correction

The measurement runner previously checked image/source and tool identities on
resume, but only appended execution conditions to the record. A changed CPU
affinity or resource limit could therefore finish an old partial batch and reuse
completed cells under different conditions.

For an ordinary comparison cell, synthetic baseline timings
`[10, 10, 10, 9, 9]` and candidate timings `[10, 10, 9, 9, 9]` pass the numerical
rules with medians 10 and 9. If the 10-second and 9-second observations came from
different environments in which both artifacts were equally fast, that relative
comparison would be invalid. This is a synthetic provenance counterexample,
not a native performance measurement or a bypass of the required 30% improvement.

The runner now binds the run, environment records, batches, warm-ups and samples
to a SHA-256 comparison identity. It checks every stored batch, including cells
with completed decisions, before writing a resumed checkpoint or skipping work.
It also checks current conditions before and after each observation, outside the
timed interval, and checks provenance before batch and final aggregation.

The stable identity includes machine identity, CPU model/topology/capabilities,
architecture, OS/kernel, Python implementation/version, GNU time version/binary,
all available process resource limits, CPU affinity, output filesystem source,
mount point/type/options, and the timing, RSS and cache policies. Load, available
memory, instantaneous CPU frequency and timestamps remain recorded diagnostics;
they are not equality gates.

Mismatch or a legacy checkpoint without provenance fails with instructions to
preserve the evidence and use a fresh evidence directory. The runner does not
rewrite rejected checkpoints or migrate old observations into a new run.
The identity is an execution-condition check, not a guarantee against ambient
load, thermal variation or changes that occur and revert between observations.
Existing noise and correctness gates remain necessary.

## Verification

`python3 tests/v11-measure-check.py` passes the existing 12 threshold controls,
74-cell matrix check and five real-process observer controls, plus the resume
checks in `tests/v11-measure-resume-check.py`.

The resume fixture drives the production `main()` checkpoint lifecycle in child
processes with real affinity/resource-limit changes and synthetic observations.
Eleven negative controls cover changed affinity/limits, mismatched warm-up,
sample, batch and environment records, legacy data, a completed-cell shortcut,
changed limits on a completed run, mid-run limit changes and the counterexample.
A same-environment resume retains the interrupted observations and completes
six fixture cells with 72 observations, despite changed diagnostic fields.
These fixtures do not claim fresh performance acceptance.

## Historical acceptance

The [original acceptance record](v1.1.0.md) remains historical evidence.
The accepted raw record has SHA-256
`6db6894dbfb0241f3930b134aeadf38f5f9b1d773130eba01e2ab30f473b1e1b`:
one environment entry, CPU affinity `[4]`, 74 cells, 74 batches and 888
observations including warm-ups. The original runner appended an environment
entry on every invocation before measuring; this record was not resumed.
No observations from the earlier unaccepted run were imported.

This correction changes only measurement tooling, tests and documentation.
It leaves runtime, measured images, workloads, numerical thresholds and the
historical sample files unchanged. The complete 74-cell comparison is therefore
not repeated or relabeled as having used the new provenance format.
