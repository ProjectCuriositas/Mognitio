# v0.15.1 package permission regression

The v0.15.0 Debian archive preserved the build temporary directory's 0700
mode as the root-owned installed payload directory. Root could launch both
commands, while ordinary users received Permission denied. Running acceptance
only as the package-installing root user missed this defect.

v0.15.1 normalizes both Debian and installer archive copies before packaging:
directories and executable files are 0755, data files are 0644. This is independent
of the build umask. The source payload, file bytes, and identity remain unchanged
by packaging. Compiler semantics and the LSP protocol are unchanged.
The CLI version label is now Mognitio, for example `Mognitio 0.15.1`.
The language server retains its `mognitio-lsp` label and wire version.

## Required checks

```sh
python3 tests/v015-package-permissions.py --payload /path/to/candidate/payload
sudo python3 tests/v015-system-package-user.py --expected-version 0.15.1
```

The archive test uses private source directories/data and umasks 022 and 077.
It inspects every archive mode, Debian ownership, identical payload bytes, and
source immutability. The installed-system test switches to unrelated UID/GID
65534 with no supplementary groups or effective capabilities, and checks both
versions, run/build/test and an LSP initialize/shutdown session.

The package-permissions workflow uses disposable Ubuntu 24.04/26.04 containers.
It checksum-pins the original v0.15.0 Debian fixture, repackages its identical
payload with the corrected packager, proves the original fails, purges it, then installs
and reinstalls the corrected fixture and runs the non-owner checks. These
same-version fixture packages are never published. dpkg preserves existing
directory modes, so the identical-build fixture requires a fresh install;
v0.15.1 receives a distinct immutable build directory. Final v0.15.1 artifacts
must additionally pass the exact CLI label and identity checks.

Run the same non-owner checks after root-owned installation and upgrade of the
final signed Debian artifact before publication. Do not replace v0.15.0 assets.

## Final signed release acceptance

After merging the accepted version into main, build and sign the frozen draft
artifacts from the immutable tag commit. Dispatch Verify frozen release packages
with the reviewed manifest SHA-256. It verifies the approved digest, commit,
version, artifact hashes, and designated bundle signature, then runs both Ubuntu
userlands through actual v0.15.0 to v0.15.1 upgrade, reinstall, purge, and fresh
install. Every successful installation is exercised as unrelated UID 65534.
Publish only after this final-artifact gate succeeds.

The acceptance workflow resolves the immutable version tag independently of its
own automation commit. This permits workflow-only repairs without moving an
existing release tag or rebuilding frozen artifacts. Draft asset visibility
requires a write-scoped token; checkout credentials are not persisted or passed
into the package-test containers.
