# v0.15.1 package permission regression

The v0.15.0 Debian archive preserved the build temporary directory's 0700
mode as the root-owned installed payload directory. Root could launch both
commands, while ordinary users received Permission denied. Running acceptance
only as the package-installing root user missed this defect.

v0.15.1 normalizes both Debian and installer archive copies before packaging:
directories and executable files are 0755, data files are 0644. This is independent
of the build umask. The source payload, file bytes, and identity remain unchanged
by packaging. Compiler semantics and the LSP protocol are unchanged.
The CLI version label is now Mognitio, for example `Mognitio 0.15.1`.
The language server retains its `mognitio-lsp` label and wire version.

## Required checks

```sh
python3 tests/v015-package-permissions.py --payload /path/to/candidate/payload
sudo python3 tests/v015-system-package-user.py --deb /path/to/candidate.deb --rootfs /path/to/ubuntu-rootfs
```

The archive test uses private source directories/data and umasks 022 and 077.
It inspects every archive mode, Debian ownership, identical payload bytes, and
source immutability. The system test extracts the package as root into disposable
storage, exposes it in a mount namespace, drops all capabilities and switches
to unrelated UID/GID 65534. It checks both versions, run/build/test and an LSP
initialize/shutdown session. It does not install packages into the host system.
Use --rootfs with a disposable supported Ubuntu userland; the host / is rejected.
The test creates a private hardlinked copy for mountpoints, leaving the base unchanged.
Use --expect-denied with the original v0.15.0 archive to reproduce the failure.

Run the same non-owner checks after root-owned installation and upgrade of the
final signed Debian artifact before publication. Do not replace v0.15.0 assets.
