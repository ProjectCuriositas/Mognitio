# v0.9.0 implementation validation

Status: Implementation complete; not released
Updated: 2026-09-28

## Scope

The implementation covers the v0.9.0 source surface, isolated compile-time
declarations, nominal types and aliases, two-axis completion proofs, explicit
templates, snapshot closures, persistent lists, explicit contract packaging,
Result-based indexing/slicing, and both execution backends.

The native pipeline uses typed SSA, independent root/liveness checks, ABI v5
indirect calls, descriptor-based tracing, owned amd64 encoding, and ELF output.
No external compiler, assembler, linker, or source interpreter is used for
native generation. The CLI validates canonical arguments before reading source.

This is a version-branch implementation record. It does not record a release,
main integration, a tag, hardware-fault tolerance, or unbounded-resource support.

## Reproduce

```sh
sbcl --noinform --script scripts/test.lisp
git diff --check
sha256sum -c verification/SHA256SUMS
```

The exact reviewed commit and command results are recorded in the implementation
PR. The manifest pins the delivered tree. Environment: Linux x86_64,
SBCL 2.6.0.debian, ASDF 3.3.1, Python 3.14.4; non-root execution and child ptrace
available. [Test coverage](../tests/README.md) identifies active fixture files.

The cumulative suite includes 70 named positive programs, static-rejection
matrices, 128 generated Boolean trees, 48 independently generated List cases,
48 independently generated scalar String cases, distributed examples, and
phase/representation/failure mutations. Counts of assertions and child processes
come from the actual run; historical suite totals are not added.

arguments with both selected panic branches. Known incompatible structure stays
rejected; unknown symbolic structure is not re-inferred after substitution.

## Lifetime and resources

The bounded-lifetime fixture allocates 14,010 objects while retaining a small
graph spanning String, product, sum, contract, closure, List, and traversal
buffer objects. Independent observation on one 4,096-byte arena recorded:

| Trigger | Collections | Reclaimed objects | Peak live bytes | Peak root bytes | Observed reuse |
|---|---:|---:|---:|---:|---:|
| Ordinary | 182 | 13,938 | 544 | 168 | 1 |
| Before every allocation | 14,011 | 13,996 | 664 | 168 | 1 |

Reuse counts one watched block lifecycle, not every reuse. Both runs preserve
the retained values. Separate tests retain an extracted child while reclaiming
its parent, and demonstrate exhaustion for intentionally growing live lists.
Host weak references observe reclamation after the bounded execution.

Fault injection enumerates allocation stages separately in host and native
paths. Tests cover closure/data/package construction, list nodes and buffers,
index/slice error objects and Result wrappers, String intermediates, failure
classification, and old-value preservation. Invalid roots, forged static flags,
corrupt buffer counts, and length/physical-size boundary metadata are tested
without allocating near the signed 64-bit length limit.

## Structural cost and collector cost

Persistent append creates one node and shares the old chain; length reads its
cached word. Indexing follows at most n links. Traversal follows n links once
to prepare an n-element buffer, then performs constant work per loop step.
The tests count node creation/link visits/buffer writes and include branching
appends from a retained old list. These bounds exclude allocator, GC, and body.

The fixed-point collector scans each reachable object's references once, but
can revisit arena headers on many passes. Controlled physical placement gives:

| Nodes | Reverse scans / passes / header visits | Forward scans / passes / header visits |
|---|---|---|
| 32 | 32 / 33 / 1,089 | 32 / 2 / 66 |
| 64 | 64 / 65 / 4,225 | 64 / 2 / 130 |
| 128 | 128 / 129 / 16,641 | 128 / 2 / 258 |

The reverse-chain case is quadratic in header visits. No linear total-GC
guarantee is inferred from a linear object-scan count.

## Publication and migration

Tests cover static failures, generation/encoding failures, temporary
write/flush/permission/close/readback failures, and failed replacement.
A previous executable retains its bytes, mode, and behavior before commit.
EIO adapters exercise both an unchanged destination and an already-replaced
destination; both are reported with replacement outcome unknown.

Successful builds are silent and do not execute the source. Outputs match
across cold/warm caches, compiler relocation, source/output names, and repeated
builds. Standalone artifacts run without the source/compiler environment.

The [migration table](../tests/README.md#intentional-migration-from-earlier-versions)
distinguishes rejected old source/CLI/ABI expectations from preserved low-level
regressions. [Initial progress](v0.9.0-progress.md) is a historical increment,
not the current completion boundary.
