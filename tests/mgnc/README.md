# Experimental compiler verification

Build the compiler with the fixed seed described in compiler/mgnc/README.md.
The regular test suite remains unchanged. These runners exercise the separate
experimental compiler and its internal phases.

## Requirements

Use non-root Linux AMD64 with Python 3, strace, bubblewrap, setfacl, bindfs and
fusermount3. Bindfs is needed for the explicit noexec observation; the runner
accepts --bindfs /path/to/bindfs without modifying the system installation.

## Focused checks

Run foundation.py, frontend.py, parser.py, checker.py, ir.py,
ir-definitions.py, encoding.py and driver-internal.py with --seed SEED.
Check generated width data with generate-width.py --check.

The v1.4 internal source snapshot, string lexer and residual terminal scanner
are checked by shared_lexer.py --seed SEED. They are isolated from the public
Driver until the shared structural parser and native bridge are ready.

Run source_profile.py, native.py, workloads.py, driver.py and faults.py with
--compiler COMPILER. Native execution can also compare against the independent
fixed seed using --seed SEED. Tests cover immutable operands, non-completion,
loop control boundaries, UTF-8 startup, primary diagnostics and publication.
Source_profile.py, native.py and workloads.py accept --evidence RESULT.json
for source/artifact hashes and per-case observations. Workloads.py exercises
runtime argument branching and accumulation with the same executable across
empty, spaced, non-ASCII and option-like arguments.

The syscall injector operates on an unchanged compiler executable. It can
replace a successful syscall reply after the side effect, which distinguishes
Unknown publication with an existing artifact from a rejected commit.

Noexec verification uses a private user-owned FUSE bind mount. When that provider
rejects atomic no-replace rename, the runner observes the public failure
separately and verifies that a successful underlying publication remains
non-executable through its noexec alias. It does not label the rejected direct
publication a success or change the output's execute bits.

Review.py adds body-boundary, mixed-comparison and exact diagnostic-location
regressions. Run it with --compiler COMPILER --evidence RESULT.json; it retains
every observation and fails if any expected acceptance, rejection or span differs.

## Frozen resource fixtures

The 21 sources and manifest in fixtures/scale are generated by scale-fixtures.py.
Metadata.py adds observed parser node counts and maximum syntax depth, comparing
the scanner token count with the independent generator count. Runtime results
come from the generator's arithmetic expectations, not the compiler output.

To regenerate before freezing a new acceptance run:

~~~sh
python3 tests/mgnc/scale-fixtures.py --output fixtures-directory
python3 tests/mgnc/metadata.py --seed SEED --fixtures fixtures-directory
~~~

Measure.py requires --compiler, --fixtures and --evidence. Defaults are one
warm-up and five measured compilations per cell. It records monotonic wall time,
wait4 peak RSS for each individual child, all process results, executable hashes,
modes and runtime results. It retains failed samples and uses a 120-second
process timeout. Each cell must have median wall time at most 30 seconds and
maximum measured RSS at most 256 MiB, with every sample correct.

Run formal measurements sequentially in a quiet environment. Record CPU, OS,
kernel, filesystem, governor, limits, swap, load and any external noise before
the run. Do not discard a slow sample without a recorded external cause.

## Isolation

Isolated.py accepts --compiler, repeated --userland base-rootfs directories and
--evidence. Each rootfs needs empty /emitter and /output placeholders and must
contain no old compiler, development toolchain or Python interpreter. It runs
compilation and generated programs separately without source or compiler
access during the latter, and traces the compiler for unexpected process execs.
The rootfs file inventory and OS identity are included in the evidence.
